# 06-软件安装部署文档

智御·OS 智能运维 Agent（OpsGuard Agent）安装部署说明。

## 1. 系统架构与依赖策略

本项目为 B/S 单体架构：一个 Spring Boot 进程同时提供 REST API（`/api/ops/**`）、MCP JSON-RPC
（`/mcp/rpc`）与静态控制台（`/`），前端为无构建步骤的原生 HTML/JS 静态文件（不使用
npm/node_modules，不引入前端构建链）。

**依赖不随包分发，安装/构建时从软件源在线获取**：
- 后端使用 Maven 管理依赖，`mvn package` 会在构建时从 Maven 中央仓库（或内网镜像）拉取
  Spring Boot、Jackson 等第三方库，安装包本身**不包含** `~/.m2/repository` 或任何预下载的
  依赖 jar。
- 运维数据采集脚本（`scripts/*.py`）为零第三方依赖，仅使用 Python 3.8+ 标准库，不涉及
  `pip install`/`site-packages` 打包问题。
- 因此本安装包体积仅为源码本身（约数 MB），首次构建需要目标机器可访问 Maven 仓库源
  （公网或内网镜像均可）。

## 2. 环境要求

| 项目 | 要求 |
|---|---|
| 目标架构 | 龙芯 LoongArch64（同时兼容 x86_64 用于开发/演示） |
| 操作系统 | 麒麟高级服务器版 V11（Kylin Linux Advanced Server V11），或其他主流 Linux 发行版 |
| JDK | 17（推荐国产毕昇 BiSheng JDK / Loongson JDK，OpenJDK 17 亦可） |
| 构建工具 | Maven 3.8+（构建期需网络访问，用于拉取依赖） |
| 内存/CPU | 最低 2 vCPU / 2GB 可用内存（已在 2 vCPU / 11GB 龙芯真机验证） |
| 磁盘 | 源码 + 构建产物约 100MB |
| 可选 | Docker + docker-compose（容器化部署）；国产大模型 API Key（DeepSeek/Qwen3，接入真实推理时需要） |

## 3. 安装包内容

```
softbei-main/
├── backend/            # Spring Boot 后端源码（Maven 工程，构建时自动拉取依赖）
├── scripts/            # 部署辅助脚本 + 零依赖数据采集脚本
├── deploy/             # 容器化/系统账户/审计规则等部署配置
├── docs/               # 项目文档（含本文档）
├── README.md
└── verify.sh           # 一键自检脚本
```

不包含：`backend/target`（构建产物）、`logs`/`rca-evidence`/`acceptance-runs`（运行时数据）——
这些均由构建/运行过程在目标机器上生成，不随安装包分发。

## 4. 源码构建与本地运行

```bash
cd backend
mvn -B clean package -DskipTests
java -jar target/ops-agent-1.0.0.jar
# 浏览器打开 http://127.0.0.1:8080/
```

默认以 `provider=mock` 推理 + `dry-run=true` 运行，无需外部依赖、无需 API Key 即可演示完整
十一阶段闭环。

### 4.1 使用一键启动脚本（推荐，含预检）

```bash
./scripts/demo-start.sh              # 默认端口 18080，Mock 模式
REBUILD=1 ./scripts/demo-start.sh    # 首次运行或代码有更新时强制重新编译
```

该脚本会自动校验 JDK 版本、（如提供 Key）预检真实模型接口连通性，并输出后端日志路径与
落盘目录。执行 `./scripts/demo-start.sh stop` 停止服务。

## 5. 容器化部署

```bash
# 在项目根目录
docker compose -f deploy/docker-compose.loong64.yml up -d --build
```

容器构建同样在构建阶段从 Maven 仓库拉取依赖，镜像内不预置依赖包。

## 6. 核心配置项（环境变量）

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `OPS_BIND_ADDRESS` | `127.0.0.1` | 监听地址；改为非回环地址前必须设置 `OPS_API_TOKEN`，否则拒绝启动 |
| `OPS_API_TOKEN` | 空（不校验） | API/MCP 入口鉴权令牌，非本机部署强烈建议设置强随机值 |
| `OPS_LLM_PROVIDER` | `mock` | `mock`（本地确定性演示）或 `deepseek`（真实模型） |
| `OPS_LLM_BASE_URL` / `OPS_LLM_MODEL` / `OPS_LLM_API_KEY` | — | 真实模型接入参数 |
| `OPS_LLM_FALLBACK_*` | 空 | 备用模型故障切换参数（可选） |
| `OPS_EXEC_DRY_RUN` | `true` | `false` 时变更类命令将真实执行，生产切换前请务必阅读第 7 节 |
| `OPS_EXEC_USE_SUDO` / `OPS_EXEC_USER` | `false` / `opsagent` | 最小权限降权执行账户 |
| `OPS_EXEC_MAX_STEPS` | `20` | 单次请求最大执行步骤数（熔断上限） |
| `OPS_EXEC_OUTPUT_AUDIT_DIR` | `logs/exec-output` | 执行输出落盘目录 |
| `OPS_EXEC_BACKUP_DIR` | `logs/backups` | 变更前恢复点目录 |
| `OPS_STATE_DIR` | `logs/state` | 待确认计划/回滚账本持久化目录（支持断点续接） |
| `OPS_TRACE_FILE` | `logs/ops-trace.jsonl` | 全链路 trace 落盘文件 |
| `OPS_DISK_CANDIDATE_MIN_SIZE_MB` | `50` | 磁盘候选门禁触发的最小文件体量 |
| `OPS_CROSSTURN_LOCKDOWN_THRESHOLD` | `60` | 跨轮攻击累积可疑度降级阈值 |

完整配置项见 `backend/src/main/resources/application.yml`。

## 7. 启用真实执行与最小权限（生产部署）

```bash
sudo OPS_USER=opsagent bash deploy/scripts/setup-ops-user.sh
```

随后设置：
```yaml
ops:
  exec:
    dry-run: false      # 谨慎：关闭后变更类命令会真实执行
    use-sudo: true
    run-as-user: opsagent
```

安全采用双重防护：应用层 `IntentRiskGuard`（四级风险裁决 + 红线阻断）与 OS 层 `sudoers`
白名单（`deploy/scripts/sudoers-ops-agent`）两道防线互为冗余，任一层失效不影响另一层生效。

## 8. 审计取证（可选）

```bash
sudo install -m 0640 deploy/auditd-rules.conf /etc/audit/rules.d/opsguard.rules
sudo augenrules --load
```

覆盖账号、sudoers、systemd 配置和数据库数据目录等关键路径的操作系统级审计。注意：auditd
只负责事后取证，不负责事前阻止；预防性控制仍由应用护栏、最小权限账号、sudoers 白名单等承担。

## 9. 部署后验证

### 9.1 快速健康检查
```bash
curl http://127.0.0.1:18080/actuator/health
curl http://127.0.0.1:18080/api/ops/runtime -H "X-Ops-Token: <令牌，若已启用>"
```
`runtime` 返回的 `llmMode`（MOCK/REAL）与 `dryRun` 字段可确认当前运行模式。

### 9.2 一键自检
```bash
./verify.sh
```

### 9.3 功能与性能证据采集（零依赖 Python 脚本）
```bash
python3 scripts/collect-functional-evidence.py --base-url http://127.0.0.1:18080
python3 scripts/collect-performance-metrics.py --base-url http://127.0.0.1:18080
```
两个脚本均为 Python 3 标准库实现，无需额外安装依赖，可直接在目标机器上运行，输出结构化
JSON 证据至 `acceptance-runs/`。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| 启动报错要求设置 `OPS_API_TOKEN` | 绑定地址非 `127.0.0.1` 时的强制安全校验，设置该环境变量后重启 |
| `mvn package` 卡住或失败 | 检查目标机器能否访问 Maven 仓库源（公网或配置内网镜像 `settings.xml`） |
| JDK 版本告警 | 确认 `java -version` 输出为 17.x，Spring Boot 3 要求 JDK 17+ |
| 变更类指令一直不真实执行 | 默认 `dry-run=true` 是有意设计，用于安全演示；生产启用见第 7 节 |
